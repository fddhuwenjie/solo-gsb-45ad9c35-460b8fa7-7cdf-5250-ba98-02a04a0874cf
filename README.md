# 直播节目串联单（Live Show Rundown）

用 **Python Flask + SQLite + 原生 JavaScript** 实现的直播节目串联单网页应用。

## 功能

- **节目设置**：设置节目起点时间与总秒数（播出开始后不可再改）。
- **分段录入**：固定时长的**赞助段**；带目标 / 最短 / 最长秒数的**访谈段**。
- **预计起止**：页面实时显示每段的预计开始与结束时间。
- **整单编辑**：一次编辑整份未播清单，可插入、删除、移动访谈段；
  播出开始后，赞助段的**时长和先后顺序不可更改**（也不能新增、删除赞助段）。
- **自动排期**：以**实际已播总时长**计算剩余时间，先沿用访谈目标时长，
  再按清单顺序在各自 `[最短, 最长]` 范围内分摊差额（剩余偏多则依次拉长、偏少则依次压短），
  **恰好排到节目终点**；无法排满或超时会给出差额秒数并**拒绝此次编辑**。
- **实况记录**：每结束当前段录入实际秒数。记录**必须保留**——即使余下清单因此无解，
  也只显示冲突提示并允许再次编辑；**已播记录不可改写**。
- **持久化**：SQLite 存储，重启后实况与待播排期完整保留。

## 快速开始（Docker，单条命令）

```bash
docker compose up --build
```

启动后访问：**http://localhost:8000**（端口 **8000**）。

- 首次启动会自动创建数据库（容器内 `/data/rundown.db`，由命名卷 `rundown-data` 持久化）。
- 停止：`Ctrl+C`；删除数据：`docker compose down -v`。

## 本地开发（不用 Docker）

```bash
pip install -r requirements.txt
python app.py
```

同样访问 **http://localhost:8000**，数据库文件为 `./rundown.db`
（可用环境变量 `DB_PATH` 指定其他路径，启动时自动建库建表）。

## 使用流程

1. **设置节目**：填写节目起点时间与总秒数。
2. **录入清单**：点「编辑整份清单」，添加赞助段（固定秒数）与访谈段（目标/最短/最长秒数），
   用 ↑ ↓ 调整顺序。编辑区会实时预览每段计划时长与差额；只有能**恰好排满**的清单才能保存。
3. **直播中**：当前段播完后，在「当前段」录入实际秒数并确认。剩余时间 =
   总秒数 − 已播实际总秒数，系统据此重新计算待播排期。
4. **冲突处理**：若实际播出与计划偏差过大导致余下清单无解，页面会显示冲突及差额
   （无法排满 / 超时各差多少秒），此时可再次编辑清单（增删移动访谈段、调整访谈范围）
   使其重新恰好排满；已播记录始终保留且不可修改。

## API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 完整状态：节目信息、已播记录、待播排期（含每段计划秒数与预计起止）、剩余时间、冲突信息 |
| POST | `/api/show` | 设置节目起点与总秒数（`start_at`, `total_seconds`）；有已播记录后返回 409 |
| PUT | `/api/rundown` | 整份替换未播清单；校验赞助段锁定与排期可行性，不可行返回 422 及差额 |
| POST | `/api/finish` | 结束当前段，录入 `actual_seconds`；记录不可改写 |
| POST | `/api/reset` | 清空全部数据，重新开始一档节目 |
